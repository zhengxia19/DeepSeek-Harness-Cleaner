# 2026-10-20 交互修正调研

范围：用户提出的五项交互修正。仅核查现有代码与 Microsoft 官方 API；本文不是实现或验收证据，未打开真实附件、未运行删除。

## 1. 执行结果报告

本地事实：`ResultsDialog.cs` 使用固定坐标及尺寸；未设置控件 Anchor/Dock；脱敏日志路径放在 Label 中；表格采用 Fill 列宽。主窗体和附件窗体均通过 `Show(this)` 打开结果窗体。已有 `OwnedFormPosition.Center` 可按 Owner 居中并限制在其屏幕工作区，附件窗体已在 OnShown 复用，结果窗体尚未复用。

官方事实：`Show(owner)` 显示非模态窗体并设置 Owner；不能仅凭指定 Owner 推定实际坐标已正确。参见 [Form.Show](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.form.show?view=windowsdesktop-10.0)。

官方事实：`TextBox.ReadOnly=true` 禁止用户编辑但允许复制；不应通过 Disabled 模拟只读。参见 [TextBoxBase.ReadOnly](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.textboxbase.readonly?view=windowsdesktop-10.0)。

官方事实：`DataGridView.ScrollBars` 默认为 Both，滚动条仍只在需要时出现；Fill 列会挤入可用宽度，只有可用宽度不足以容纳列的 MinimumWidth 时才需要横向滚动。参见 [ScrollBars](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.datagridview.scrollbars?view=windowsdesktop-10.0)、[列尺寸模式](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.datagridviewautosizecolumnmode?view=windowsdesktop-10.0)。

建议：复用现有居中方法；采用可伸缩布局和最小窗体尺寸，将日志路径改为可聚焦的只读 TextBox。结果表格明确允许双向滚动，采用可调整固定初始列宽，或为 Fill 列设置合理 MinimumWidth；不能仅增加 Both 属性就视为修复。通过长路径、多行结果、缩小/放大窗体验证日志、按钮和表格无重叠，且能滚动至最后一行、最后一列。

## 2. 附件右键打开

本地事实：`AttachmentsForm.cs` 使用 ListView，当前无右键菜单或打开操作。`AttachmentInventoryService.cs` 支持以 sha256 作为无扩展名对象文件名的路径；`AttachmentIndex.cs` 从会话提取名称和类型展示信息。类型展示文本不等同于已校验文件格式。

官方事实：`ProcessStartInfo.UseShellExecute=true` 通过系统 Shell 打开具备已注册默认打开动作的文档；.NET 默认值为 false，应显式设置。不能保证任意扩展名、任意机器都有可用关联；Process.Start 还可能因文件不存在、权限等失败。参见 [UseShellExecute](https://learn.microsoft.com/en-us/dotnet/fundamentals/runtime-libraries/system-diagnostics-processstartinfo-useshellexecute)、[Process.Start](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.start?view=net-10.0)。

建议：菜单绑定右键命中的单一记录，与删除勾选状态分开。打开前重新检查附件白名单、普通文件、reparse/越界及文件变化；FileName 使用确定的本地文件绝对路径，不拼接命令行，不把名称或类型文本当成可执行命令。错误显示明确且不终止程序。

无扩展名文件的方案边界：不能承诺原路径直接默认打开成功。若采用临时副本，必须先有与该附件对象对应的可信 mediaType/格式证据，按明确白名单映射扩展名；在独立临时目录复制并核对副本，再调用系统默认应用；不改名或修改真实附件。名称后缀、显示标签或冲突类型不能充当格式确证。类型未知或无默认关联时提示原因。临时副本方案是项目建议，不是 Microsoft API 自动提供的行为；实施任务应明确副本目录、大小限制和保留/清理策略，防止关闭程序时误删仍被外部应用使用的文件。

## 3. 主窗体位置和尺寸

官方事实：.NET 5 及以后，单文件发布的 `AppContext.BaseDirectory` 为宿主可执行文件所在目录，适合定位用户指定的同目录设置文件。参见 [AppContext.BaseDirectory](https://learn.microsoft.com/en-us/dotnet/api/system.appcontext.basedirectory?view=net-10.0)。

官方事实：`RestoreBounds` 表示普通状态的矩形，官方注明仅在 WindowState 非 Normal 时有效；保存偏好应结合 WindowState。参见 [Form.RestoreBounds](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.form.restorebounds?view=windowsdesktop-10.0)。

建议：正常关闭成功时保存；Normal 保存 Bounds，其他状态保存 RestoreBounds。恢复时先设置 Manual 及正常矩形，再恢复最大化状态；最小化关闭下次按普通状态恢复。配置只含版本、坐标、尺寸和窗口状态，不含会话内容。文件缺失/损坏/非法数值使用默认布局；显示器移除或工作区变化时校正位置和最小尺寸；目录不可写时提示但允许退出，不提权、不写注册表或静默换目录。需覆盖不同启动工作目录、普通/最大化/最小化关闭、配置损坏和只读目录。

## 4. 扫描列表全选

本地事实：`MainForm.cs` 的选择列名为 `checked`，是禁止排序的 DataGridViewCheckBoxColumn；已有单元格提交处理。

官方事实：`ColumnHeaderMouseClick` 在点击列标题时触发，可读取列索引处理指定列。参见 [ColumnHeaderMouseClick](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.datagridview.columnheadermouseclick?view=windowsdesktop-10.0)。

建议：点击“选择”表头切换当前筛选结果的勾选；全部已勾选则取消，否则全选。必须操作 checkbox 值及现有选择集合，不能用 SelectAll 替代勾选；隐藏筛选外记录不得被顺带新增勾选。保留当前实现已有的跨筛选勾选时，须显示隐藏勾选数量，删除确认列出完整实际选择集，不能声称仅删除当前显示行。处理当前编辑提交、空结果、部分已勾选、排序后表头、扫描/删除进行中禁用及筛选切换；用合成会话证明删除计划与完整勾选集合一致，改变隐藏勾选保留规则需另外确定。

## 5. 所有表格表头加粗居中

本地范围：主窗体与结果报告使用 DataGridView；附件管理与删除确认使用 ListView。需同时覆盖，不限主窗体。

官方事实：DataGridView 可通过 ColumnHeadersDefaultCellStyle 设置表头样式；主题绘制由 EnableHeadersVisualStyles 控制。参见 [ColumnHeadersDefaultCellStyle](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.datagridview.columnheadersdefaultcellstyle?view=windowsdesktop-10.0)、[EnableHeadersVisualStyles](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.datagridview.enableheadersvisualstyles?view=windowsdesktop-10.0)。

官方事实：ListView 的第一列忽略 ColumnHeader.TextAlign，始终左对齐；微软明确提出可用 DrawColumnHeader 自绘解决。OwnerDraw 配合 Details 视图可自绘表头；DrawItem/DrawSubItem 可用 DrawDefault 保留系统绘制。参见 [ColumnHeader.TextAlign](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.columnheader.textalign?view=windowsdesktop-10.0)、[OwnerDraw](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.listview.ownerdraw?view=windowsdesktop-10.0)、[DrawItem.DrawDefault](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.drawlistviewitemeventargs.drawdefault?view=windowsdesktop-10.0)、[DrawSubItem.DrawDefault](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.drawlistviewsubitemeventargs.drawdefault?view=windowsdesktop-10.0)。

建议：抽取统一表头样式；DataGridView 只修改表头字体及对齐；ListView 仅自绘表头背景和粗体居中文本，行和子项保持默认字体、勾选及选择效果。不得直接把整个表格 Font 改粗。实现后验证第一列表头、水平滚动、列宽拖动、主题/高对比度、100%/150%/200% DPI；若启用列重排/排序，需验证对应交互和标识。字体随控件生命周期释放，DPI/字体变化后重新生成；这些是实施验收要求，当前未验证。

## 调研结论

五项均可在既定 C#/.NET 10/WinForms 方案内完成。主要实现陷阱为 Fill 模式没有产生预期横向滚动、ListView 第一列表头无法仅靠 TextAlign 居中，以及无扩展名附件缺少默认打开关联。任务应记录上述边界及 Windows 实测要求；本文不表示任何修复已完成。
