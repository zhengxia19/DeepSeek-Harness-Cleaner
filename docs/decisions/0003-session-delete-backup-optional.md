# ADR-0003：会话/附件删除的 ZIP 备份由强制改为可选（确认与复验保留）

- 状态：已接受（v0.2.0，N-04；决策 D1/D4 经用户确认）
- 日期：2026-10-19
- 关系：修订 ADR-0002 第 2 条（“必须备份并校验后才可删除”）；其余条款不变。

## 背景

v0.1.x 将会话与附件删除硬性要求“先创建经 SHA-256 校验的原始 ZIP 备份”。实际使用中：小体量会话/附件的备份步骤使删除流程冗长，且备份 ZIP 本身占用磁盘、需要管理；用户希望直接删除已确认不再需要的数据。同时删除误操作风险已由多层门禁覆盖，备份并非唯一防线。

## 决策

1. **会话删除与附件删除的备份门禁改为可选（建议）**：计划 `RequiresBackup=false`；删除确认对话框“确认删除”按钮初始即可用，备份状态标签显示“未备份（可选，建议）/已备份并校验”。
2. **确认仍是必需门禁（D4）**：删除必须在确认对话框点击“确认删除”（`userConfirmed=true`），未确认一律 `GATE_NOT_CONFIRMED` 中止、零删除。
3. **其余安全机制原样保留**：Harness 进程运行中阻断删除；逐文件删除前复验路径白名单/重解析点/根指纹；计划记录的 SHA-256 与 mtime 复验（内容变化即跳过该项）。即“可以不备份，但不是盲删”。
4. **提供备份时防呆保留**：调用方提供 manifest+ZIP 时，executor 仍逐项校验（损坏/缺失/签名不符 → `GATE_BACKUP_INVALID` 中止、零删除）；`RequiresBackup=true` 的计划（调用方显式要求）仍必须备份齐备。
5. 缓存/桌面清理规则不变（本就无强制 ZIP）；结果报告如实标注备份位置（未备份时为空/占位）。

## 替代方案

- 维持强制备份：误删可恢复性最好，但日常小删除成本高、备份目录膨胀；用户明确选择放宽（D1）。
- 完全移除备份选项：损失可选保护层；拒绝。
- 仅会话放宽、附件保持强制：用户明确否决（D1：附件同样放宽）。

## 影响

- `docs/requirements.md` REQ-011/REQ-014、`docs/design.md` §5/§7/§8、`docs/interfaces.md`、`docs/testing.md` TC-11/TC-14、`README.md`、`CHANGELOG.md` 同步放宽表述。
- AGENTS.md §2 删除红线由“必须有经校验的 ZIP 备份 + 确认”修订为“必须明确确认 + 计划复验；备份可选（建议）”。
- 误删且未备份时不可恢复；UI 以“未备份（可选，建议）”明示，结果报告如实标注无备份。
- 冒烟断言反转：“未备份时确认按钮禁用”→“未备份时确认按钮可用”；保留“已备份校验通过才删”路径。
