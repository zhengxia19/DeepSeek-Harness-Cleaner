# 需求规格（Requirements）

状态：方案 B 已确认；行为契约待代码与真实测试验证。目标：Windows 10 x64 / Harness 0.2.0.0。

## 1. 项目边界与用户

- 单机单用户、本地离线工具；只能读取用户明确授权的 Harness 数据根，不能调用/修改 Harness 服务或模型接口。
- 会话原始日志是源数据，投影缓存非源数据；UI、统计、备份、清理不得将缓存当成唯一事实源。
- 不提供云端撤回、上报控制、修改消息、自动回导、自动时间计划、自动后台清理、系统服务、多用户权限管理。
- 用户提供本机路径/容量是只读快照，不保证开发时仍一致；真实文件身份和关联必须在运行时再次验证。

## 3. 非功能需求

- **NFR-01 数据安全：** 不上传内容；日志默认不含消息文本、绝对私人工作区路径或凭据；ZIP 在用户选择的本地路径生成，不自动同步云端。
- **NFR-02 性能：** I/O 异步后台执行；测试机为 Windows 10 x64、SSD、8GB RAM；1000 个小会话（总原始数据 ≤200MB）列表元数据初扫目标 ≤15 秒；滚动/筛选响应目标 ≤200ms；性能未达标作为发布阻断或形成明确的用户批准豁免。
- **NFR-03 内存：** 事件按流解压解析，限制单行默认 8MiB、单会话解压字节默认 256MiB、预览最多 2000 条文本记录；超限可原始备份但不得假装解析完整。压力样本进程工作集目标 <512MiB。
- **NFR-04 可靠性：** 失败不影响其他未选文件；不宣称跨文件事务性删除；重新扫描与清理结果保持一致。
- **NFR-05 易用性：** 中文 UI，键盘可达、DPI 100%/150% 可用；危险操作有明确二次确认、没有自动清理。
- **NFR-06 环境：** 不依赖 Node、Python、数据库、管理员权限或 Harness 运行中的进程。
- **NFR-07 兼容：** 支持本地实测 Harness 0.2.0.0 会话布局；新格式默认只读识别/阻断删除；不把 GitHub master 自动视为安装版本。

## 4. 不可越过的发布条件

1. `REQ-002/009/011/015/020` 及相关 TC 全通过。
2. 在目标 Windows 10 实机/隔离 VM 上构建发布包并进行自包含启动、退出与 UI 测试；记录具体 Edition、Version、Build（参见官方 .NET Windows 10 支持限制）。
3. 用脱敏真实样本**只读**验证版本代际、复用缓存关系和字段命名；不能获取样本则对应语义能力标记未支持且不得对不确定数据执行清理。
4. 数据目录不允许指向项目源代码、系统目录、用户根目录等非 Harness 结构。

## 5. 需求变更管理

本文件唯一维护 REQ/NFR 编号。需求变更必须同步对应 TC、`implementation-tasks.md` 的关联、`design.md` 的数据契约，并进行一次复审；不允许仅增加 UI 按钮而不修改测试。
